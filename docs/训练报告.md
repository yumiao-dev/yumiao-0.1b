# Yumiao-0.1B 训练报告

> 一台 AMD MI308X、8 小时内的单次训练能跑出什么水平的 0.1B 中文模型 —— 过程、坑与结论。

## 一、目标

从零训练一个 **1 亿参数**的中英双语基座模型，语料规模 8B tokens，再叠加自我认知 SFT，产出一个可以正常对话、知道"自己是谁"的最小可用模型。

选 0.1B 不是因为它强，而是因为它**便宜到可以完整跑一遍全流程**：数据清洗 → 分词器训练 → 预训练 → SFT → 评测 → 导出。所有环节都自己做一遍，比直接用现成模型有价值。

## 二、硬件与环境

| 项 | 值 |
|---|---|
| GPU | AMD Instinct MI308X（gfx942 / Card SKU M3080202），205.8 GB HBM |
| CPU / 内存 | 23 核 / 200 GB |
| 软件 | ROCm 7.2.53、PyTorch 2.12、vLLM 0.28.0+rocm723 |
| 单次实例上限 | 8 小时（平台限制），配额 100 小时 |

实测吞吐（随机初始化 Transformer，bf16）：

| 配置 | 吞吐 |
|---|---|
| 1.27B 参数 | 11,945 tok/s |
| 117M / seq 256 / bs 128 | 136,520 tok/s |
| 117M / seq 1024 / bs 64 | 88,500 tok/s |

最终训练稳定在 **89,500 tok/s**，与理论值一致 —— 说明 0.1B 模型在 MI308X 上完全是访存/调度受限，算力大量闲置。

## 三、数据

### 3.1 来源

| 数据集 | 原始体积 | 用途 |
|---|---|---|
| `AI-ModelScope/chinese-c4` | 22.9 GB / 96 zst 分片 | 中文主力 |
| `wikipedia-cn-20230720-filtered` | 0.52 GB | 中文知识密度补充 |
| `HuggingFaceFW/fineweb-edu` CC-MAIN-2024-10 | 31 GB / 20 parquet，取前 5 个 | 英文 |

### 3.2 清洗

1. HTML 标签与实体剥离（`BeautifulSoup` + 正则兜底）
2. 繁简统一（`opencc`，全部转简体）
3. 全半角归一（NFKC），连续空白折叠
4. 段落级去重（SimHash，汉明距离 ≤ 3 视为重复）
5. 质量过滤：长度 50–100k 字符；中文字符占比 ≥ 30%；符号占比 ≤ 30%；含 `<script>` / 明显的 SEO 垃圾页丢弃
6. 英文额外过滤：Gopher 规则（重复 n-gram、停用词比例、平均词长）

### 3.3 分词与落盘

自训 BPE，词表 32,000。训练样本：8 万条 × 1,500 字符流式喂入（避免一次性载入 OOM）。

**中文压缩率 1.61 字符/token**（GPT-2 词表约 1.0–1.1），主要收益来自中文常用词合并与全角标点单 token 化。

分词结果写成 uint16 二进制分片（`np.memmap` 读取，训练时零拷贝）：

| 分片 | 数量 | tokens |
|---|---|---|
| `zh-*.bin` | 144 | 6.00 B |
| `en-*.bin` | 80 | 3.71 B |
| `wiki-*.bin` | — | 0.21 B |
| 合计 | — | **9.919 B** / 19 GB |

实际训练消耗 8.0B（未跑满语料池）。

## 四、模型

标准 LLaMA 解码器，**不含任何花哨改动**：

```
vocab 32000, d 768, layers 12, heads 12, kv_heads 4, head_dim 64,
ffn 2048 (SwiGLU), rope_theta 10000, rms_norm_eps 1e-6, ctx 1024
参数量 100.1M（embedding 与 lm_head 共享，省 24.6M）
```

初始化：线性层与 embedding 正态 `std=0.02`；残差输出投影（`w3` / `wo`）用 `std = 0.02 / sqrt(2 × 12)`，抑制深层残差累积。这一条在 12 层上影响不大，但在 24 层以上是必需的。

## 五、预训练

| 项 | 值 |
|---|---|
| 优化器 | AdamW，β=(0.9, 0.95)，wd=0.1 |
| 学习率 | 6e-4，warmup 2000 步，余弦衰减到 10% |
| batch | 64 × 1024 = 65,536 tokens/步 |
| 梯度裁剪 | 1.0 |
| 精度 | bf16 autocast |
| 步数 | 122,000（8.0B tokens） |
| 耗时 | ≈ 24.7 小时（731 ms/步） |
| 最终 | **loss 2.96 / ppl 19.3** |

loss 曲线形态：前 2,000 步从 10.4 快速降到 4.2，之后进入长尾；40% 处（3.2B）到 5.5 附近，80% 处（6.4B）到 3.3，最后 20% 只从 3.3 降到 2.96 —— 明显进入收益递减。以这个规模，8B 之后再喂数据的边际价值很低，更该做的是加参数或提数据质量。

## 六、踩过的坑（按严重程度）

### 1. 双重 shift —— 模型在学"预测 t+2"

DataLoader 已经把 `x` 切成 `ids[:-1]`、`y` 切成 `ids[1:]`，而 `model.forward` 内部又做了一次 `logits[:, :-1]` 对齐 `targets[:, 1:]`。

症状很隐蔽：loss 正常下降，生成却总是"跳字"。诊断方法是把同一段文本按三种对齐方式各算一次 loss：

```
current = 2.95   correct(t+1) = 8.56   offset2 = 2.95
```

`current` 与 `offset2` 相等，说明模型实际学的是错位两位的映射。**修复后 `current == correct`**，这一条是所有 bug 里代价最大的。

### 2. 数据没 shuffle —— 38% 的训练里一个中文 token 都没见

分片按文件名顺序读，`en-*` 排在 `zh-*` 前面。前 46,000 步全在英文上跑，中文占比为 0。

修复：`DataLoader(shuffle=True)` + 分片级随机采样。**教训：任何多语料混合训练，第一个 batch 就要打印语言分布。**

### 3. SFT 标签泄露 —— loss 0.0004，输出"威士威士"

`input_ids` 与 `labels` 直接同一份，没有右移一位，模型学的是"复制输入"。loss 掉到 0.0004 时才发现。

修复：`__getitem__` 返回 `ids[:-1], labels[1:]`。修完 loss 回到 1.6–1.8 的正常区间。

### 4. ROCm 上 `cross_entropy(ignore_index=-100)` 反向直接崩

```
hipErrorLaunchFailure (719)
```

只在 `ignore_index` 参与反向时触发，ROCm 7.2 的 kernel 缺陷。绕法：不用 `ignore_index`，手动构造 mask，把 label 里的 -100 `clamp(min=0)` 后正常算交叉熵，再乘 mask 求平均。多花 3 行代码，稳定复现。

### 5. SFT 学习率用了 1e-4

1e-4 是 7B 级别微调的常规值，放到 100M 模型上直接把权重打散 —— 身份问答全对，但"1+1"答"约 1 亿"，典型灾难性遗忘 + 身份数据串位。

改 **5e-5**，同时把身份数据从 3,500×2 epoch 降到 1,000 条 × 1 epoch，混入 3,000 条通用指令，loss 从 1.6 回到 2.43，"1+1" 能答 "2.0"。

### 6. 贪心解码必然复读

`do_sample=False` 下输出："中国是美国的，而美国是美国的，而美国是美国的……"

这不是权重问题，是 0.1B 模型分布过于尖锐 + 上下文重复惩罚缺失。改用采样（temp 0.7–0.8 / top_p 0.9 / repetition_penalty 1.15–1.3）后，同一权重输出立刻正常。

**结论：小模型的解码策略比模型本身更影响观感。**

## 七、SFT

### 7.1 数据构造

`FACTS` 事实表驱动生成，覆盖 20+ 个身份维度（名字、训练者、参数量、层数、维度、注意力配置、词表、上下文、语料规模、知识截止、硬件、是否开源、能否联网/看图等），每个事实配 6–10 种问法、3–5 种答法，随机组合。

两版数据：

| 版本 | 构成 | 结果 |
|---|---|---|
| A | 3,500 条身份 × 2 epoch | 身份 6/6 全对，但 "1+1" 答"约 1 亿" |
| B（发布版） | 1,000 条身份 + 3,000 条通用指令，1 epoch | 身份 2/2 对，"1+1" 答 "2.0" |

B 版通用指令来自 `alpaca-gpt4-data-zh`，筛 30–900 字符（太长会超 512 上下文，太短信息量不足）。

### 7.2 训练

只在 assistant 片段算 loss；prompt 与 system 段 label 全部 -100。lr 5e-5 余弦衰减，bs 8×512，500 步，最终 loss 2.43。

### 7.3 评测（人工，采样解码）

| 问题 | 回答 | 判定 |
|---|---|---|
| 你是谁 | 我是 Yumiao-0.1B，一个 1 亿参数的语言模型，由 yumiao 训练。 | ✅ |
| 谁训练的 | yumiao。 | ✅ |
| 猫是什么 | 猫是一种哺乳动物，……（笼统，不精确） | ⚠️ |

## 八、结论

1. **0.1B / 8B tokens 的能力上界很清楚**：语言形式学得会，世界知识学不会。loss 2.96 对应的 ppl 19.3，意味着模型对下一个 token 仍高度不确定，任何需要精确事实的任务都不可靠。
2. **训练流程的坑远多于模型设计**。双重 shift、未 shuffle、标签泄露这三个 bug 每个都能让 loss 曲线"看起来正常"但模型废掉。
3. **解码策略的收益被严重低估**。同一个 checkpoint，贪心解码是复读机，采样解码是可用的聊天模型。
4. **ROCm 可用但有坑**。整体吞吐与理论一致，但 `cross_entropy(ignore_index)` 这类边角 kernel 会直接崩，长跑训练必须在启动前把 loss 路径跑通。
